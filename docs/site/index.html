1. Download and set up

The direct runtime requires Linux x86-64. The available binary was built on Ubuntu 24.04; compatibility with older glibc systems is not established. macOS requires a locally built extension and a Linux Docker worker.

Download the Linux binary

Download native-linux-results from the successful build while signed in to GitHub. Unzip it, then extract native/geosupport-0.2.0-Linux-x86_64.tar.gz. It contains geosupport.duckdb_extension and documentation.

Or use the GitHub CLI from a clone of this repository:

git clone https://github.com/SPTKL/duckdb-geosupport.git
cd duckdb-geosupport

# Ubuntu 24.04: tools and runtime libraries for the CI binary.
sudo apt-get install -y make curl unzip libcurl4t64 libssl3t64

gh run download 39054761799 --repo SPTKL/duckdb-geosupport \
  --name native-linux-results --dir build/download
mkdir -p build/native
tar -xzf build/download/native/geosupport-0.2.0-Linux-x86_64.tar.gz \
  -C build/native geosupport.duckdb_extension

# Download the repository's pinned DuckDB 1.4.4 CLI.
make fetch
export GEOSUPPORT_HOME="$PWD/.cache/geosupport"

There are no versioned GitHub Releases yet. CI artifacts expire; if this artifact is unavailable, use a newer successful CI build or build below. INSTALL geosupport FROM community is not available.

Build from source instead

Clone the repository as above. Install dependencies, then build:

# Debian / Ubuntu
sudo apt-get update
sudo apt-get install -y build-essential libcurl4-openssl-dev \
  libssl-dev curl unzip

make fetch
make -j2 test
export GEOSUPPORT_HOME="$PWD/.cache/geosupport"

The binary is build/native/geosupport.duckdb_extension. On macOS, use Xcode Command Line Tools and the system curl libraries, then run the same Make commands.

macOS: configure the Linux worker

Build the extension from source, start Docker, and run:

docker build --platform linux/amd64 -f Dockerfile.runtime \
  -t duckdb-geosupport-runtime:0.2.0 .
export GEOSUPPORT_RUNTIME=docker

Set this before starting DuckDB. On Linux x86-64, leave GEOSUPPORT_RUNTIME unset or set it to local.

Open DuckDB

build/deps/duckdb -unsigned -bail -init /dev/null \
  -cmd "LOAD '$PWD/build/native/geosupport.duckdb_extension';"

Use an absolute path to the binary. The SQL extension name and binary filename remain geosupport and geosupport.duckdb_extension.

2. Install a release and run a query

Run the following in DuckDB. The first command explicitly downloads the NYC engine and data, approximately 195 MiB compressed and 1.9 GiB installed.

CALL gs_install('26c');

SET VARIABLE geosupport_release =
  (SELECT bundle_id FROM gs_load('26c'));

CREATE TEMP TABLE result AS
SELECT gs_address('125', 'Worth St', 'Mn') AS geo;

SELECT geo.bbl, geo.bin, geo.latitude, geo.longitude,
       geo.grc, geo.grc2
FROM result;

gs_load starts the worker. The variable selects the default for this connection. Alternatively, pass release := '26c' directly to a lookup. Data is stored in GEOSUPPORT_HOME, separately from your DuckDB database.

3. Examples

Geocode a table

CREATE TEMP TABLE addresses AS
SELECT * FROM (VALUES
  (1, '125',    'Worth St',          'Mn'),
  (2, '350',    '5 Ave',             'Mn'),
  (3, '30-30',  'Thomson Ave',       'QN'),
  (4, '999999', 'NOT A REAL STREET', 'Mn')
) AS t(id, house_number, street_name, borough);

CREATE TEMP TABLE geocoded AS
SELECT id, gs_address(house_number, street_name, borough,
                      release := '26c') AS geo
FROM addresses;

SELECT id, geo.bbl, geo.bin, geo.latitude, geo.longitude,
       geo.grc, geo.grc2
FROM geocoded ORDER BY id;

Keep house numbers and identifiers as strings. Rejected addresses remain rows with return codes and messages. Inspect both grc and grc2 for an address lookup.

SELECT id, geo.grc, geo.grc2, geo.message, geo.message2
FROM geocoded
WHERE geo.grc IS DISTINCT FROM '00'
   OR geo.grc2 IS DISTINCT FROM '00';

This filter flags anything other than two exact 00 codes for review; your acceptance policy may allow other codes.

Look up a tax lot or building

SELECT (gs_bbl('1001680032', release := '26c')).bbl AS bbl;
-- 1001680032

SELECT (gs_bin('1001831', release := '26c', mode := 'tpad')).bbl AS bbl;
-- 1001680032

Call a Geosupport function directly

SELECT gs_call('1E', to_json({
  'house_number': '125',
  'street_name': 'Worth St',
  'borough_code': 'Mn'
}), release := '26c', mode := 'extended') AS geo;

Every result includes raw, the full parsed output as JSON text. Use geo.raw::JSON to inspect function-specific fields.

Use another quarter

CALL gs_install('26b');
SELECT (gs_address('125', 'Worth St', 'Mn', release := '26b')).bbl AS bbl;
-- 1001680032

Save release, engine_version, and bundle_id with your results. An explicit release overrides the connection variable. Prepared statements capture that variable when prepared.

4. Function reference

Lookups

SignaturePurpose
gs_address(house_number, street_name, borough, release := NULL)Address lookup using function 1B, regular mode.
gs_bbl(bbl, release := NULL, mode := 'regular')Tax lot lookup using BL.
gs_bin(bin, release := NULL, mode := 'regular')Building lookup using BN.
gs_call(function_code, inputs, release := NULL, mode := 'regular')Generic call with a JSON object of input fields.

Accepted modes: regular, extended, long, tpad, long+tpad, extended+tpad. Output depends on the function and mode. gs_address does not implement a separate 1A/1E fallback.

Inputs must fit their fixed field widths and contain ASCII without NUL. Generic field values may be strings, integers, booleans, or NULL. Individual NULL fields become blanks. A NULL generic function, entire input value, or mode returns NULL when a release is selected.

All supported Geosupport function codes and aliases

See the layout definitions for input field names, widths, and function-specific layouts. _gs_call is an internal implementation function; use the public helpers above.

Returned fields

FieldTypeMeaning
bbl, binVARCHARTax lot and building identifiers.
latitude, longitudeDOUBLECoordinates, when available.
grc, grc2VARCHARPrimary and secondary return codes.
message, message2VARCHARCorresponding engine messages.
releaseVARCHARQuarterly release label, e.g. 26c.
engine_versionVARCHAREngine version, e.g. 26.3.

Unavailable result fields are NULL. Not every function returns coordinates or both return codes.

Release management

SQLPurpose
SELECT * FROM gs_available_releases();List catalog releases (26B and 26C).
SELECT * FROM gs_installed_releases();List installed bundles.
SELECT * FROM gs_runtime_info();List active workers.
CALL gs_install('26c');Download, verify, and install a release. Repeated calls verify and reuse it.
CALL gs_import('26c', '/path/linux_geo26c_26.3.zip');Import a matching base archive offline.
CALL gs_verify('26c');Verify bundle integrity.
CALL gs_load('26c');Start a worker and return the bundle identity.
CALL gs_unload('26c');Stop a worker; keep installed data.

These functions return release, bundle_id, engine_version, platform, and details (JSON text). Geocoding never installs missing data automatically.

VariableDefault / purpose
GEOSUPPORT_HOME~/.cache/duckdb-geosupport; bundle store.

Store/catalog settings are captured on first use; runtime settings apply at worker startup. Calls are serialized, with up to eight workers and a bounded per-worker cache. Lifecycle changes are outside SQL transactions. Cancellation and external-access policy integration remain unfinished; use trusted analytical sessions.

5. Errors and return messages

Address rejects are data: inspect grc, grc2, message, and message2. The extension preserves messages from the selected NYC engine, so their text depends on the input and quarterly release.

API and runtime failures stop the query. DuckDB may prefix these messages with Invalid Input Error.
